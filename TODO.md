# Upstream

The reasoning is in lima/yolobox.md#an-empty-page-means-limas-forwarder-died. The lima side is done: lima-vm/lima#5557 was closed, PR #5558 merged, and the fix shipped in lima v2.2.1. What remains is the nixos-lima change below.

- nixos-lima PR [nixos-lima/nixos-lima#125](https://github.com/nixos-lima/nixos-lima/pull/125): `restartIfChanged = false` on `lima-init` and `lima-guestagent`, because a nixpkgs bump alone restarts them and, on lima v2.1.2 through v2.2.0, that triggers the dead-forward bug. Still open and unmerged.
  - Once it is merged and this flake's `nixos-lima` input is bumped, this repo's own pin (`systemd.services.lima-guestagent.restartIfChanged` and `lima-init.restartIfChanged` in `nix/base.nix`) becomes redundant: remove it.
- lima: `limactl stop` (and the stop half of `limactl restart`) can hang on the `vz` driver, seen on lima 2.2.0 and 2.2.1, with no isolated trigger. Symptom: after about three minutes `did not receive an event with the "exiting" status`; the hostagent took SIGINT, stopped some forwards, and never exited, and a child `limactl hostagent` may spin at high CPU and outlive `limactl stop -f` of its parent. `LimaDriver.stop` prints its recovery text. Recovery: `kill -9` the hostagent (and the spinning child); under vz that also ends the VM. A gentler route is `sudo systemctl reboot` inside the guest (`yo ssh sudo systemctl reboot`), though the child still needs `kill -9`.
- nixpkgs: each user bus logs `Ignoring duplicate name 'org.freedesktop.systemd1'` (and `portable1`, `machine1`, `import1`) at error level, once per user manager. NixOS's dbus module writes `<servicedir>…-system-path/share/dbus-1/services</servicedir>` into `session.conf`, and `<standard_session_servicedirs/>` in the same file scans `XDG_DATA_DIRS`, whose `/run/current-system/sw/share` is that same directory, so dbus-broker reads every file twice. Harmless; it needs a nixpkgs change (drop the explicit servicedir, or dedupe), not one here.

## Several machines

`yo -m NAME` (see `yo.md#several-machines`) shares some host-global state. Each item below breaks, or is weaker, once two or more boxes run at once; nothing was changed for them:

- The LUKS key is one 1Password item (`yolobox-disk`) and the passphrase derives from it alone, so every instance's disk opens with the same passphrase. Whoever holds it for one box holds it for all, and rotating it needs every disk re-keyed.
- The AWS broker has one socket (`~/.local/state/yolobox/aws-broker.sock`) and one watched pid (`ensure_aws_broker`, `broker_needs_restart` in `yolobox_cli/aws.py`). When two boxes are up, each `yo` run restarts the broker to watch its own box's keepalive pid, and stopping the watched box ends the broker, so the other box loses its AWS credentials until its next `yo` run. Only matters where `aws` is installed and has SSO profiles.
- `lima/yolobox.yaml` mirrors guest TCP ports 1024-49151 onto the host's 127.0.0.1, same number on both sides. Two running boxes that listen on the same port collide: the second hostagent cannot bind it and lima logs the failure while the first box keeps the port. The same mirror is the port-mirror squat in the [Security backlog](#security-backlog).
- On a Mac, `LimaDriver.verify_initrd_listener` checks only that the instance's ssh port is above the range lima mirrors (49151). It does not check who holds the port. Another account on the same Mac that binds `127.0.0.1:<port>` while the instance is stopped therefore receives the passphrase on the next `yo up`, because the initrd connection pins no host key. The libvirt driver checks the listener's owner with `ss`. Candidate fix: require `lsof -nP -a -p <hostAgentPID> -iTCP:<port> -sTCP:LISTEN` to list the hostagent before each send. It needs a Mac to confirm that the hostagent itself, and not a child `limactl hostagent`, holds the listener. An existing instance on a port at or below 49151 is refused on `yo up` until `limactl edit` moves it.

## Linux host

- `yo bootstrap` on a libvirt host once stayed alive, with no child process, after the host's OOM killer had ended the domain shortly after its unlock. Reading the code found one wait that did not look at the domain, `wait_for_operator`, which could have probed the dead port for up to 600 s; it now reads `domstate` between probes (`docs/linux-host.md#a-domain-that-dies-under-yo`). Whether that wait was the whole hang is not known: the run was not timed. If a `yo` process hangs again, record how long, and take its Python stack (`py-spy dump --pid PID`) before killing it.
- The `--memory` ceiling (`memory_refusal`, `docs/linux-host.md#sizing-a-box`) counts other active domains at their max memory and keeps a fixed 4 GiB for the host. Unchecked: the default 16 GiB (on purpose, see the doc), a shut-off domain started later, what the host's own processes use beyond the reserve, and host swap. The reserve is a guess, not a measurement. If boxes are still OOM-killed under the rule, measure a working host (`MemAvailable` with the boxes up) and raise the reserve, or warn on stderr when the default 16 GiB does not fit either.
- `yo up --disk N` is not held to the pool's free space. `virsh pool-info --bytes default` reports `Available`, so the check would be cheap, but the volume is a sparse qcow2: a 250 GiB disk on a pool with 200 GiB free is created and boots, and fails only when the guest fills it. A refusal would forbid that deliberate overcommit; a note on stderr when `N` exceeds `Available` would not.
- An unprivileged `yo` cannot verify that the egress table is loaded: `nft list table` needs root, so `check_libvirt_host` sees only `systemctl is-active yolobox-host.service`. An operator who deleted the table without stopping the unit (see `linux/host-setup.md#the-host-table`) leaves a unit that reads `active` and a host with no table. Candidate fix: a root-owned oneshot that writes the table's presence to a world-readable file, or a handle `yo` can read without privilege.
- The owner check before each passphrase send (`LibvirtDriver.verify_initrd_listener`) is not atomic with the ssh connect, and a port with no listener passes it. A local process that binds the box's loopback port in that gap would receive the answer to the initrd's ssh handshake. The port sits above the kernel's ephemeral range, so only a deliberate squat can do it. Candidate fix: have ssh connect through a descriptor `yo` verified with `SO_PEERCRED`-style checks, or pin the initrd's host key through the domain.
- A box on a Linux host with global IPv6 has a global address, where a Mac box has none (`docs/linux-host.md#ipv6`). Both egress tables reject the same v6 ranges, but a LAN machine with a global address cannot be told from the internet. Candidate fix: give the domain no IPv6 (passt `--ipv4-only`, if libvirt exposes it) and say so in the story.
- aarch64 Linux host under libvirt is unsupported. The libvirt driver pins an x86_64 seed (`SEED_NAME` and `SEED_SHA512` in `yolobox_cli/libvirt.py`). `libvirt/domain.xml` is x86_64 q35: `arch x86_64`, `machine q35`, `<apic/>`, a sata cidata disk and `isa-serial`. A `virt` machine would need `machine='virt'`, no `apic`, a virtio or scsi cidata disk and a pl011 serial. `linux/host-setup.sh` installs `edk2-ovmf`, which is x86_64 firmware; aarch64 needs `edk2-aarch64`. The domain allowlist in `yolobox_cli/libvirt_host.py` assumes the q35 shape. The NIC name `enp0s1` (in `nix/base.nix`, `nix/egress.nix` and the yolobox-network `rules.nix`) assumes PCI slot 1 on q35. `nix/base.nix` turns `virtualisation.rosetta` on for every aarch64 guest, because today only Lima/vz on Apple silicon runs one; an aarch64 libvirt guest has no `vz-rosetta` share and would wait on that mount at boot, so it needs a gate of its own on a fact the guest can see (the share's virtiofs tag, say), never on the host OS (`nix/base.md#no-host-os-in-the-guest`).
- `yolobox.network.lanAllow` has no effect on a Linux host. `linux/yolobox-host.nft` rejects the private ranges for passt's uid, and the host table has no counterpart of the guest's allow set. It is documented (`docs/linux-host.md`, `nix/egress.md`). Candidate fix: have `host-setup.sh` take the same networks and render an accept set into the host table.
- `yo destroy --yes` on libvirt powers the domain off at its undefine step (`undefine_domain` calls `force_stop`) if it started since the steps were listed. A `virsh start` that lands between that state read and `virsh undefine`, or between the undefine and `vol-delete`, is still not excluded. Candidate fix: one per-machine lifecycle lock that `yo up` holds from its status read through `start()` and `yo destroy` holds throughout, taken before the unlock lock everywhere.

## Guest

- `nix/display.nix`'s `waitForX` polls for the X socket with `sleep 0.2`, 150 times, and its message hardcodes 30s: it orders openbox after Xvfb by the clock. Candidate fix: Xvfb's `-displayfd` readiness, or a systemd `Type=notify` or `.socket` arrangement.
- Kernel bugs behind unprivileged user namespaces. The agent can `unshare -Urn`, become root of its own namespace and make the kernel autoload `nf_tables` and the net/sched modules, whose bugs have given root before (CVE-2024-1086, CVE-2023-32233, CVE-2022-2588). The box keeps user namespaces because the chromium sandbox, rootless podman and the nix build sandbox need them, and it keeps `nf_tables` because the firewall and podman's bridge networks sit on it. The net/sched half is closed: `nix/hardening.nix` blocks every `cls_*`, `act_*` and `sch_*` module except `sch_fq_codel`. The `nf_tables` half has no fix at the box level, so its only mitigation is a current kernel (`linuxPackages_latest` in `nix/base.nix`). See `nix/hardening.md#known-residual-the-surface-behind-user-namespaces`.
- An existing `/etc/yolobox/local.nix` that sets `yolobox.hardening.extraWrappers` as a list fails its next rebuild with a type error, since the option is now a set from wrapper name to capabilities (`nix/hardening.md` has the migration). The release notes of the release that ships the change must carry the migration. Check before the release: grep the notes for `extraWrappers`.
- `herdr-server.service` has no guard against the host's `remote-client-bridge` starting a server first. Once the unit's server is down, `Restart=on-failure` waits `RestartSec=5`, and in that gap the bridge can start its own `herdr server`; the unit then loops on `already running` forever (see [nix/herd-server.md](nix/herd-server.md#a-switch-leaves-the-server-running)). Nothing on the box's side can close this with herdr 0.9.5, checked against its source at the tag and its docs:
  - Socket activation is out. `herdr server` binds both sockets itself through one function (`bind_local_listener`, `src/ipc.rs`) and reads no `LISTEN_FDS`. Its "already running" check is a connect probe on the socket path, so a systemd-held socket would make it exit as already running.
  - The bridge has no connect-only mode. `remote-client-bridge` takes only `--idle-timeout-v1`, and it spawns `<exe> server` (with `setsid`, in the bridge's own cgroup) whenever the client socket does not answer. Upstream: herdrdev/herdr#4291, "no attach-only option", open.
  - `RestartPreventExitStatus` cannot single the loop out. "already running" exits 1, like every other failure; only the stderr text differs.
  - The fix has to come from herdr: an attach-only bridge (#4291), or a server that adopts inherited sockets. Until then `restartIfChanged = false` keeps switches out of the gap, and only a crash opens it. Recheck when bumping `yolobox.harness.herdr.version`.

# Security backlog

Open security items. Each one names its evidence and a candidate fix.

- Port-mirror squat (medium). Lima mirrors guest TCP ports 1024-49151 onto the host's `127.0.0.1`, minus the small deny-list in `lima/yolobox.yaml`. An agent can bind an in-range port before a host tool does, and a host connection to that `127.0.0.1` port then reaches the guest listener, so real bytes cross. Usually the squat only denies the port, because the host tool then fails to bind. But a browser that navigates to `localhost:PORT` for a dev or OAuth flow, whose real server never bound, would reach the guest. Candidate fixes: shrink the mirror range, extend the deny-list with known callback ports, or make the mirror opt-in per port. Reproduction: as the agent, bind `0.0.0.0:34567` in the guest, then on the host run `nc -z 127.0.0.1 34567`. With several boxes the same mirror makes their ports collide, see [Several machines](#several-machines); a Linux host has no such mirror (`docs/linux-host.md#host-ports`).
- The 1Password forward exposes every vault key (high blast radius, as designed). The forwarded agent serves every key in the vaults `agent.toml` names, because it filters by vault only. That includes the disk key (`yolobox-disk`) and any git or cloud keys in those vaults. `LUKS_SIGN_DATA` is public and the derivation is deterministic, so one approved `yolobox-disk` signature yields the disk passphrase. The per-sign 1Password prompt is the only gate. Candidate fix: a per-key or per-item filter, or a dedicated forwarded socket that exposes only what the box needs.
- Supply chain: the flake ref is a movable tag with no rev pin (high, as designed). `yo` builds from `github:aka-rider/yolobox/v<version>`. The release workflow force-moves that tag. `nixos-rebuild` runs as root in the guest and fetches the mutable tag, which also builds the initrd and the LUKS unlock. So an owner, token or tag compromise gives root in the guest and in the initrd on the next operator-initiated rebuild. The agent cannot trigger this, so it is trust-on-first-use. The harness installers are also unpinned `curl | bash`, which stays contained to the agent. Candidate fix: have the host pass a rev and narHash that the guest verifies, and checksum the installers.
- The libvirt sizing commands were written against the documented behaviour, not run on a live host: `virsh setmaxmem`/`setmem`/`setvcpus --config` (with `--maximum` first) on a shut-off domain without a balloon, `dominfo`'s `CPU(s)` line for a shut-off domain, and `vol-resize` of a qcow2 volume were checked only against the fake host in `tests/test_yo_libvirt.py`. Run `yo down && yo up --memory N --cpus C` and `yo up --disk G` once on a libvirt host and fix what differs.
