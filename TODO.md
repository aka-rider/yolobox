# Waiting on upstream

- [nixos-lima/nixos-lima#125](https://github.com/nixos-lima/nixos-lima/pull/125) sets `restartIfChanged = false` on `lima-init` and `lima-guestagent` upstream. Once it is merged and the flake's `nixos-lima` input includes it, delete the two `restartIfChanged` pins in `nix/base.nix` and the matching rule in `CONSTITUTION.md`.
- [herdrdev/herdr#4291](https://github.com/herdrdev/herdr/issues/4291): `remote-client-bridge` has no attach-only mode. While the `herdr-server` user unit restarts, the host's bridge can start a server of its own outside the unit, and the unit then fails with "already running" until that server is killed. `restartIfChanged = false` in `nix/herd-server.nix` keeps switches out of that gap; only a crash opens it. When the option ships, have the host connect attach-only.
- [herdrdev/herdr#4833](https://github.com/herdrdev/herdr/issues/4833) (open): herdr's own selection and copy mode in machine panes copies server-side, so the text never reaches the Mac clipboard. Separately, the Mac client drops a Clipboard message from a machine that is not the active one; not yet reported.
- lima, not yet written up: `limactl stop yolobox` hangs on lima 2.2.0's `vz` driver with `did not receive an event with the "exiting" status`, and a child `limactl hostagent` spins at ~99% CPU and outlives `limactl stop -f`. Seen 2026-09-05, 2026-09-28 and 2026-10-01, with no trigger isolated. Recovery: `yo ssh sudo systemctl reboot`, then `kill -9` the spinning child. File it once a narrower repro exists.
- fedora `selinux-policy`, not yet filed: `virtqemud_t` may not execute the qemu hooks in `/etc/libvirt/hooks/qemu.d/`, which carry the correct label `virt_hook_t`. Each domain start logs `denied { execute }` and `denied { execute_no_trans }` for `scontext=virtqemud_t tcontext=virt_hook_t tclass=file permissive=1`. The hook runs only because `virtqemud_t` is a builtin permissive type (`semanage permissive -l`), so it stops once that domain is enforcing. The same denial was fixed for `virtnetworkd_t` and the network hook in selinux-policy 40.24 (bug 2276917). Seen with selinux-policy-44.12-1.fc44 and libvirt-daemon-driver-qemu-12.9.0-1.fc44. To reproduce, put an executable hook in `qemu.d/`, run `restorecon -F` on it, restart `virtqemud`, start a domain and run `ausearch -m avc -c qemu-event`. `linux/yolobox-virt-hook.cil` allows both permissions locally until the policy does; delete it, its step in `linux/host-setup.sh`, its line in `nix/pkgs/yolobox.nix` and the matching lines in `README.md` and `AGENTS.md` then.
