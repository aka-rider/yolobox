# Setting up a Linux host

`linux/host-setup.sh` is the one place that changes the Linux host system-wide. An operator runs it once with `sudo bash linux/host-setup.sh`, and again after anything below drifts. `yo` never uses sudo on the host: when a precondition is missing, it names the installed copy of this script. The script is idempotent, so a second run changes nothing and exits 0. When a step fails, it prints `host-setup: failed during: <step>` on stderr, and the step letter below is in that line. The steps do not run in letter order: (h) runs first, (d) runs before (b) and (c), and (j) and then (l) run before (g). Each step's text says why.

## Why each step

- **(h) Resolver.** First, before anything is installed or enabled, so a host that fails it is left as it was. passt serves the guest's DNS at the gateway address, and forwards it to the host's resolver only when that resolver is on the host's loopback. When the first `nameserver` line is a LAN address, passt hands that address to the guest, and the guest would talk to a LAN machine. The script refuses and tells the operator to point the host at a local resolver. systemd-resolved's stub on 127.0.0.53 qualifies. Failure looks like `the first nameserver in /etc/resolv.conf is ..., not a loopback address`.
- **(a) Repository and packages.** Fedora's own libvirt is too old for step (b). The Virtualization SIG's `virt-preview` COPR carries a newer one. `acl` provides `setfacl`, which step (j) uses and `yo` reads back with `getfacl`. `passt-selinux` is part of the list because libvirt starts passt under the SELinux type `passt_t`, and without the policy module that start is denied.
- **(d) Daemons.** This runs before (b) and (c) on purpose, because `virsh -c qemu:///system` needs a running virtqemud. virtnetworkd starts too, only so the `default` network can be switched off. Socket activation keeps the daemons idle when nothing connects.
- **(b) Version gate.** libvirt passes the guest's gateway address to passt only since 12.2.0. Older versions leave passt to copy the gateway from the host, and then the box's address plan (guest 192.168.5.15, gateway 192.168.5.2) cannot hold. The gate reads the daemon's version from the `Running against daemon:` line of `virsh version --daemon`, not `virsh --version`: the daemon is what starts passt, and a daemon that `dnf` upgraded but did not restart still runs the old code while the client reports the new one. It runs after (d) because it needs the daemon. The check compares each dotted field as a number. Failure looks like `the libvirt daemon is 12.0.0, older than 12.2.0`: the COPR is not enabled, `dnf` kept the distribution's build, or the daemon needs `systemctl restart virtqemud`.
- **(c) The default network off.** libvirt ships a `default` network that autostarts a bridge and a NAT. Every box here gets its network from passt, and a bridge on the host is a path the guest was never meant to have. So if a network named `default` exists, the script disables its autostart and destroys it when it is active, and prints what it did. It does not undefine it, and it touches no other network: the host may use libvirt networks for other machines. A package upgrade may turn the autostart back on. Run the script again, and check that `ip -o link | grep -c virbr` prints 0, unless another network of yours has a bridge.
- **(e) Polkit.** Without a rule, every `virsh` call from the operator asks for a root password. The rule grants `org.libvirt.unix.manage` to the account that ran sudo, and to no one else. The account name goes into a JavaScript file, so the script first refuses anything that is not a plain account name.
- **(f) Account `yolobox-vm`.** Every domain is labelled with this uid and gid, so QEMU, and passt with it, run as `yolobox-vm`. A uid of its own is what lets step (g) tell the guest's traffic from the operator's. The account has no home and no login shell.
- **(j) The passt socket directory.** libvirt starts passt under the domain's DAC label, so passt runs as `yolobox-vm`, but libvirt creates `/run/libvirt/qemu/passt` owned by `qemu` with mode 0755. passt then cannot create its socket, and `virsh start` fails with `Failed to bind UNIX domain socket: Permission denied` (SELinux is not the cause: `passt_t` may write `qemu_var_run_t` directories). The step installs `/etc/tmpfiles.d/yolobox-passt.conf`, which creates the directory the way libvirt does and adds an ACL entry `u:yolobox-vm:rwx` with the mask `m::rwx`, then applies it at once (tmpfiles, then `setfacl -m` with the same entry, which is idempotent). `/run` is a tmpfs, so tmpfiles re-applies it on each boot before virtqemud starts. The mask is spelled out because an ACL entry is only as wide as the mask: when libvirt later `chmod`s the directory for another passt domain, the kernel recomputes the mask from the group bits (`r-x`), and `getfacl` then shows `user:yolobox-vm:rwx #effective:r-x`, so passt's bind fails again. The explicit mask survives a tmpfiles re-apply, which leaves the mask alone, but not that `chmod`. Step (l) installs a libvirt hook that re-applies the entry and mask after such a `chmod`. `yo up` still reads the ACL with `getfacl` just before `virsh start`, and refuses with the one-line fix `sudo setfacl -m u:yolobox-vm:rwx,m::rwx /run/libvirt/qemu/passt` and the advice to re-run `host-setup.sh`, which installs the hook. Check by hand with `getfacl /run/libvirt/qemu/passt`.
- **(l) The passt ACL hook.** Installs `linux/yolobox-libvirt-hook.sh` as `/etc/libvirt/hooks/qemu.d/50-yolobox-passt` (mode 0755, `restorecon -F` for its SELinux label), then `systemctl try-restart virtqemud.service`, because virtqemud reads its hook directory only when it starts. Running domains survive the restart. See [The passt ACL hook](#the-passt-acl-hook).
- **(g) The host table.** See below.
- **(i) Pool.** Domains reference volumes in the libvirt pool `default` and never files under a home directory, because sVirt would not let QEMU read those. The script defines, builds, starts and autostarts the pool at `/var/lib/libvirt/images` only for the parts that are missing.
- **(k) Operator key.** Last, because it changes nothing. It asks the operator's 1Password agent (`~/.1password/agent.sock` in the account that ran sudo, via `sudo -u`) for its identities and compares only the comment, which must be exactly `yolobox-operator`. The summary prints the create-the-item reminder only when no identity matches. When the socket is missing, the agent is locked or has no identities, or `ssh-add` is absent, the summary says it could not check and why, because a silent pass would hide a missing key.

## The passt ACL hook

libvirt runs every executable in `/etc/libvirt/hooks/qemu.d/` at points of each domain's life, as `HOOK <domain> <operation> <sub-operation> <extra>` with the domain XML on stdin. `50-yolobox-passt` acts at three of them and runs one fixed command, `setfacl -m u:yolobox-vm:rwx,m::rwx /run/libvirt/qemu/passt`:

- `prepare begin`, for a yolobox domain only (its XML carries the `https://github.com/aka-rider/yolobox` metadata namespace of `libvirt/domain.xml`): before libvirt starts passt for it, so passt can bind its socket;
- `started begin` and `release end`, for any domain: after libvirt started another domain, and so possibly another passt that reset the mask, and after one went away.

Every other operation exits 0 and prints nothing, because for some (`migrate begin`, `restore begin`) libvirt reads the hook's stdout as a replacement XML. The XML is only searched for the namespace; no value from it reaches a command, and the hook never calls virsh, because libvirt holds the domain while a hook runs. It reads all of stdin first, so libvirt never writes into a closed pipe.

A failed `setfacl` always prints `yolobox passt hook: setfacl on ... failed` on stderr, which libvirt logs (`journalctl -u virtqemud`). What it stops depends on whose start it is. At `prepare begin` of a yolobox domain the hook exits non-zero and libvirt does not start the domain: loud, as the alternative is a passt that cannot bind. At `started begin` and `release end`, which run for every domain on the host, the hook exits 0 after logging. Otherwise a hook left behind on a host whose `yolobox-vm` account was deleted would stop every VM there from starting. Before any passt domain ran, the directory may not exist yet; the hook then has nothing to fix and succeeds. `yo up` keeps checking the effective permission before every start, so a host where the hook is missing or failed still gets the one-line fix. `tests/test_libvirt_hook.py` runs the hook with a fake `setfacl`, and `tests/test_consistency.py` keeps its directory, account and namespace equal to `yo`'s and the template's.

To remove the hook, delete it and restart virtqemud, which reads the hook directory only when it starts:

```sh
sudo rm /etc/libvirt/hooks/qemu.d/50-yolobox-passt
sudo systemctl try-restart virtqemud.service
```

Running domains survive the restart. Remove it with the `yolobox-vm` account; a hook left behind only logs a failed `setfacl` at every other domain's start.

## The host table

passt has no destination filter. It turns every guest connection into a plain `connect()` on the host, so a guest that reaches the gateway address reaches anything the host can reach: its own services on loopback and on its LAN address, the tailnet, and the LAN behind it. `nix/egress.nix` blocks that inside the guest, but the agent runs in the guest, and a guest rule is only as safe as the guest. The host table is the layer the guest cannot undo.

`linux/yolobox-host.nft` hooks output and judges one uid. The first rule accepts every uid but `yolobox-vm`, so the operator's own traffic is never touched. Replies of established connections pass. Of what remains, only DNS to 127.0.0.0/8 may use loopback (the gateway address is passt's DNS), and every other loopback packet is rejected, including `::1` on IPv6. Then the same private, CGNAT, link-local, multicast and broadcast ranges that `nix/egress.nix` blocks are rejected. Keep both sets equal to that file's `blockedV4` and `blockedV6`.

Two properties of the unit matter:

- **No `ExecStop`.** Stopping the unit must never open the host, so the table stays loaded. To remove it when you mean to, first stop the unit (`systemctl stop yolobox-host.service`), then delete the table by hand with `nft delete table inet yolobox-host`. Deleting the table while the unit stays active leaves a unit that reports `active` and a host with no table.
- **`RequiredBy=virtqemud.service` and `Before=`.** virtqemud does not start until the table is in place, and a failed table keeps it from starting at all. The table is replaced atomically on a reload: the file defines the table, deletes it and defines it again in one transaction, so a file with an error leaves the old table untouched.

The table needs the account from step (f) to exist, because nft resolves `yolobox-vm` to a uid when it loads the file. That is why (f) comes before (g), and why running `nft -f` on the file by hand on a machine that has not run the script fails with `User does not exist`.

Recognising a missing table: `nft list table inet yolobox-host` fails, or `systemctl is-active yolobox-host.service` does not print `active`. Recognising a working one: from inside a box, `curl` to the host's LAN address times out or is refused, while name resolution still works.
